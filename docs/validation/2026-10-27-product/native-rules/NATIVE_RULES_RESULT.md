# Native Android.mk reference build — 2026-10-27

The genuine Rockchip Android 7.1.2 GNUmake rules now compile, link, run their relocation-packer/strip rules, and install `gralloc.rk30board.so` and `hwcomposer.rk30board.so` in a disposable thin reference tree. This advances beyond the earlier manual compiler/linker invocation. It does not build the complete Android product or establish graphics functionality on RK3229.

`attempt-11-clean-android-native.log` records an empty-output-directory build before patch0007: 12 HAL C++ units, 7 libunwind units (2 C++, 3 C, 2 assembly), and 1 compiler-rt C unit, yielding 2 genuine static source modules and 2 installed HALs. The reference Android.mk declares 22 real prebuilt DSO modules, of which 13 prebuilt targets are processed for this build. The dynamic linker also resolves their runtime dependencies. There are no stub DSOs or replacements of BUILD_SHARED_LIBRARY.

The successful clean build exposed a real bug: the unsupported NV12_VIDEO pixel format 0x16 logged an error and proceeded with uninitialized size and stride. Patch0007 returns `-EINVAL` immediately. An independent host function-boundary regression executes the exact extracted function: baseline has 3 expected failures (it reaches recording allocators), corrected source passes 14 checks including rejection/no output publication, null outputs, neighboring formats, alignment and allocation routes. This uses host type/log/allocator fixtures and does not verify Android ABI or GPU execution.

`attempt-12-gralloc-input-fixed.log` records the successful real Android.mk rebuild after that one-line fix. The upstream version.sh regenerates timestamp headers, so version consumers in both HALs also rebuild. No rebuild follows the passing final checks. Baseline artifacts/logs/hashes and loader results are retained separately; `artifacts/` contains only the final corrected modules.

The final two modules pass 5 Android ARM32 linker/QEMU Linux-user-mode metadata cases: 2 positive HAL loads and 3 negative cases (missing file, missing HMI, wrong id). The helper uses RTLD_NOW, checks tag/id/method pointers and prints versions/name. It never calls HAL open. Constructors/destructors may run. The legacy linker warning about the existing probe's DT_FLAGS_1 flags is preserved. No rendering, framebuffer/ION/RGA operation, full Android boot, SD boot or board validation occurred.

The actual shared CRT objects were previously compiled from pinned Bionic source using Linaro6.3.1 with softfp and are reused through supported CRT override variables. The HALs and selected linked runtime archives use genuine Android GCC4.9, and the two real LLVM static modules use genuine Android Clang3.8. The earlier hardfloat Linaro libgcc link attempt failed; it was replaced with the real Android toolchain, without ABI warning suppression or archive aliases. Genuine host relocation packer, linker plugin, legacy ncurses ABI5 runtime libraries, and upstream Clang resource-directory alias are recorded in acquisition provenance. No system package mutation was needed.

The platform DSOs are 21 actual official SDK API25 ARM32 reference libraries plus pinned Rockchip vendor libion. They serve only this link/loader experiment. They are not source-built platform libraries, not copied into the new product profile, and are excluded from the delivery package.
